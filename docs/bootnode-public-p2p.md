# Update bootnode bindings and public enodes

Public bootnode bindings are generated by `setup render` from the saved spec.
Existing AWS NLB metadata is read by `setup aws`; `rpc export` resolves public
peer addresses while preserving the saved node identities. Infrastructure must already
provide one NLB per node, a TCP 30303 listener, an IP target group and frontend
security groups. Partner allowlists remain infrastructure-owned.

## Inputs

The deployment spec needs only these resource references per enabled node:

```yaml
bootnodePublicP2p:
  - index: 0
    enabled: true
    existingNlb:
      targetGroupArn: REPLACE_WITH_TCP_IP_TARGET_GROUP_ARN
      securityGroupIds: [REPLACE_WITH_NLB_FRONTEND_SG_ID]
```

The spec must also identify the AWS account, region, EKS cluster and bootnode
count under `infrastructure`. `mode: existing` is inferred when `existingNlb` is
present. Optional NLB references disambiguate target-group association. Listener, subnet
and EIP references are not needed by generated values.

Declare the bindings before planning. Complete the saved preparation stages,
then run from the generated deployment directory:

```bash
scrollsdk setup aws --dir .
# Complete genesis and the intervening stages before rendering.
scrollsdk setup render --dir .
```

Render uses the frozen `.scrollsdk/intent.json`; editing the original spec does
not amend a saved plan. There is no standalone values-overlay command or automatic
migration of an existing funded deployment. Do not restart genesis or funding to
change bindings; an existing deployment needs a reviewed migration preserving its
identities and receipts.

Resource discovery only reads facts used by configuration. Infrastructure tooling
owns IAM, routing, source restrictions and network validation. There is no
infrastructure audit in deployment-preflight.

Generated production values use the chart's uppercase `ARN` spelling:

```yaml
reth:
  p2pExternal:
    enabled: true
    mode: existing
    ordinal: 0
    existingNlb:
      targetGroupARN: REPLACE_WITH_TCP_IP_TARGET_GROUP_ARN
      securityGroupIds: [REPLACE_WITH_NLB_FRONTEND_SG_ID]
```

Each release uses ordinal zero; the spec index identifies the release. Use the
paired l2-reth chart 0.1.11 or later. Metadata and generated values do not establish
P2P reachability. After Helm installation, verify actual registered Pod targets.

Verify partner RLPx identity and block synchronization separately. For external
RPC packages, pass the same `--spec` to `rpc export`; it discovers EIPs
from AWS for existing NLB bindings instead of relying on ClusterIP Service status.

See [the NLB runbook](existing-nlb.md) for AWS prerequisites and recurring
partner changes, and [spec modes](spec-bootnode-public-p2p.md) for the separate
Service-owned NLB workflow. Existing Service-owned public endpoints require an
explicit migration; the existing-NLB workflow does not adopt their resources.
